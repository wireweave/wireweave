# Wireweave deterministic runtime and output

Contract: `core/runtime`. Language `4.0.0`; execution profile `standard-1`.

## 1. Input and output boundary

Runtime consumes the immutable linked model produced under [LANGUAGE.md](LANGUAGE.md), a fixed Profile and fixture definitions. It does not parse DSL, resolve names heuristically or discover product intent from labels. State machine inspection, transition extraction, canvas projections and standalone HTML consume that same model. Core does not contain provider calls, account APIs, billing, interviews or host canvas navigation.

| Output                       | Required contents                                                                                                                      | Execution claim                                                                                      |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| fragment                     | Escaped HTML, scoped CSS, logical/source map, diagnostics, requirement references                                                      | Insertable visual/semantic tree; native controls can respond, but full app execution is not asserted |
| canvas                       | Fixed-size board fragments, x/y/width/height, logical screen/variant IDs, source maps, total bounds                                    | Review projection; coordinates and editor next/previous controls do not create product routes        |
| app                          | One standalone UTF-8 HTML document, neutral CSS, fixed official runtime, validated linked registry/fixtures/assets, integrity manifest | Authored controls execute supported operations without Studio APIs or server fallback                |
| svg                          | SVG viewBox of selected boards, semantic titles/descriptions, export manifest and unsupported-feature diagnostics                      | Static representation; foreignObject support is recorded in the output profile                       |
| json / design-system mapping | Canonical model or typed mapping with loss/unsupported reports                                                                         | No invented interactions or implied Figma import/round-trip capability                               |

App export emits no partial success. All required modules, referenced assets, state scopes, routes, fixtures and registry records must validate first. Fragment preview may display an invalid draft only with an explicit invalid result and source diagnostics. Error-recovered ASTs never enter app compilation. A valid specified obligation is not a compile error; it is explicitly unexecuted functionality.

## 2. Runtime state and event order

The store contains the current route, instantiated shell/screen/component scopes, overlay stack, focus-return stack, fixture cursors, virtual clock, pending requests, queue, sequence counter and reset generation. DOM values are projections of this store. Native controls provide input events; they do not constitute a second persistent state store. No hidden localStorage/cookie/IndexedDB persistence is performed. Reload restores initial fixture/state at the addressed route. Persistence beyond this lifetime requires a separately declared product capability, never a renderer default.

A semantic event starts an activation. Each synchronous segment of that activation is one transaction; awaiting a simulated result suspends it and the continuation runs in a new transaction. Earlier committed segments are not rolled back when a later segment fails. The order is:

1. Capture normalized event data and source instance identity. Reject events from inactive, hidden, disabled or detached owners. Keyboard modifiers for link opening retain native browser meaning.
2. For input/change, normalize the native value to the binding type, apply code-point length and numeric constraints, and stage the bound state update. IME composition is not committed until compositionend; input events during composition do not dispatch user handlers.
3. For submit, run form validation before its handler. Invalid controls expose messages, the first invalid control receives focus, and no submit operation executes. No browser form action request is sent.
4. Read the handler guard against the staged state snapshot. A false guard records `guard-false`, commits a valid input binding if present and runs no operations.
5. Validate all operation shapes/dependencies statically, then evaluate the next synchronous prefix in declared order against current instances, stopping at simulate or the end. The next operation reads prior staged writes. Invalid types, invalid references, forbidden targets or exceeding a limit abort this segment without a partial state/route commit. At simulate, stage pending status and reserve its output states; do not execute its following operations yet.
6. Publish the new state once, render visible/enabled/selected/pending/error outcomes, perform the final requested focus action, and append a trace entry. Focus-induced events enqueue after this commit; they do not re-enter the transaction.
7. Dispatch the validated fixture request with its immutable activation/operation ID, reset generation and virtual deadline. Its queued completion transaction publishes result/status/error state, records the operation outcome, and resumes following operations according to after/onFailure. It never mutates state during another transaction. A continuation revalidates live instances and reads their then-current state; its captured event payload remains the original normalized event.

One handler exists per element/event/key. Events process FIFO by `(virtualTime,sequence)`. For a route change, pending-request cancellation is staged first; exit handlers run synchronously in the departing live scopes before unmount and before the route commits. Exit order is page then departing layout; enter order is new layout then page. A retained layout has neither exit nor enter for a page-only route change. They read the staged state. Only set/reset/toggle/filter/sort/close effects are permitted in exit, so exit cannot await or navigate recursively. An exit failure aborts the complete route segment, including its staged cancellations. After successful exit, departing overlays close and mount-lifetime scopes unmount; the route commits, then enter events enqueue for active destination scopes. Both lifecycle phases count toward the same microstep bound. Session-lifetime state remains associated with its stable owner ID and restores on remount. Shared shell state remains mounted while the route uses the same shell/profile instance.

`concurrency=drop` rejects reactivation of a handler with pending simulation as `busy`; `queue` enqueues it after the earlier activation. Default source shorthand is drop. The queue stores normalized input snapshots, not live DOM objects. A timeout, reset or unmount invalidates matching pending request identities. Late responses record `stale-response` and cannot update another instance or generation.

## 3. Operation contract

Every Operation has id, executionClass, effect, after, onFailure and obligationRefs. Operation IDs are unique across every handler of the same owner; handler IDs are independently unique on that owner. `after` names earlier operations of the same activation; forward/self references or dependency cycles are errors. Array order is execution order. A dependency must have succeeded, rather than merely returned. `onFailure=continue` allows only subsequent operations that do not depend on the failed operation. Trace records failures and skipped dependents; continue does not turn the activation into passed.

| Effect                         | Required inputs and exact behavior                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| navigate                       | Typed screen or URL target and history=push/replace. Resolve screen before commit; apply route lifecycle. An external target is a declared browser navigation with no claim about destination availability.                                                                                                                                                                                                     |
| navigateBack / navigateForward | Move within this app's history entries; at either boundary leave state unchanged and expose `history-boundary`. Never close an overlay as a substitute.                                                                                                                                                                                                                                                         |
| set                            | Evaluate expression and replace a declared state with a value of its type; record/list replacement is immutable.                                                                                                                                                                                                                                                                                                |
| reset                          | Restore one state declaration's initial value; does not change route, fixtures or other states.                                                                                                                                                                                                                                                                                                                 |
| toggle                         | Negate boolean state; non-boolean target is a compile/type error.                                                                                                                                                                                                                                                                                                                                               |
| open / close / toggleOverlay   | Address a modal/drawer/popover/dropdown in the owner scope; apply stack/focus lifecycle. Reopening an open target is idempotent and does not duplicate focus records.                                                                                                                                                                                                                                           |
| focus                          | Focus an enabled visible focusable element after commit; invalid target errors before mutation.                                                                                                                                                                                                                                                                                                                 |
| validate                       | Validate the addressed form, exposing native and declared constraints; failure stops dependents and focuses the first invalid control.                                                                                                                                                                                                                                                                          |
| filter                         | Read a list of records, query string and field. Keep records whose field's string value contains the query after locale-independent lowercasing; empty query copies the list. Missing/non-string fields error. Write a new list to target.                                                                                                                                                                      |
| sort                           | Read a list of records and homogeneous string/number field; stable sort ascending/descending, preserving original index for ties. Missing/null/mixed-type fields error; the source list is unchanged.                                                                                                                                                                                                           |
| simulate                       | Address fixtureRef, resultState, statusState, errorState and positive timeoutMs. All three state refs are distinct; statusState is string with initial idle, errorState is record with initial {}. Invocation writes pending and clears error; success writes result, succeeded and {}; error/timeout preserves result, writes failed and structured error data. The continuation starts only after completion. |
| specify                        | Present the referenced implementation obligation and record `specified-unexecuted`. It performs no external effect and cannot satisfy a success dependency.                                                                                                                                                                                                                                                     |
| resetScenario                  | End the current activation and reset route to entry, all state, fixture cursors, clock, overlays, selection, validation messages and queue; increment reset generation.                                                                                                                                                                                                                                         |

executable accepts all effects except simulate/specify; simulated accepts only simulate; specified accepts only specify and requires at least one obligation reference. One interaction can combine the classes. An external implementation obligation can also accompany an executable or simulated operation; creating a simulation does not discharge that obligation.

A source form submit with local validation, simulated authentication and route navigation is represented as ordered operations. The navigation depends on successful simulation; simulated authentication can never be recorded as server authentication success. UI errors and retries are authored state/operations. Runtime supplies their mechanism, not product-specific messages or business decisions. Guards such as statusState=failed expose an authored denial message; correcting form values and submitting again consumes the next fixture step. This failure branch is observable without converting a denied result into navigation success.

## 4. Fixture scheduling and reproducibility

Profile.clockStartMs initializes an integer virtual clock. A Fixture contains id, nonempty ordered steps and exhaustion policy. Each step has delayMs, outcome=success|error|timeout and a JSON value. Cursors are scoped to the app reset generation, not globally shared across runs. Each call atomically consumes the next step. Exhaustion either yields `fixture-exhausted` or reuses the last step according to the explicit policy; it never fabricates a success response.

The automatic browser scheduler advances virtual time monotonically from the host monotonic timer. The conformance driver pauses it and calls advanceClock(deltaMs), producing the same ordered due events for the same inputs. Wall-clock date, timezone, Date.now and Math.random are not exposed to expressions. Authored clock values are absolute fixture data. For equal deadline and response time, timeout is processed first. Due events at equal time use request sequence order. A zero-delay response is queued after the initiating transaction, never delivered inline. There is no hidden jitter.

Fixture errorState receives `{code,value,operationId}`. A declared error step uses code=`fixture-error` and its JSON value; timeout uses code=`timeout` and value=null; exhaustion uses code=`fixture-exhausted` and value=null. A runtime type/limit rejection remains a diagnostic and is not relabeled as a fixture response. The status/result/error refs are reserved by the pending request. Another handler or binding attempting to write a reserved state receives `state-busy`; reads remain allowed. Completion/cancellation releases those reservations. Unmount cancellation releases every reservation even when the request owner is being removed. It writes status=cancelled and error `{code:"cancelled",value:null,operationId}` to each target state whose lifetime survives that unmount, including app, retained shell and session-lifetime local state. Only removed mount-lifetime targets omit the write. The result is preserved; queued activations for the departing owner are cancelled. Reset restores initial state instead. outcome=timeout completes at the request deadline and does not expose its value as a success result. The resultState type must accept every success step before compilation. Reset cancels pending scheduled events by generation and restores all cursors. Pausing, sleep/wake and browser throttling may delay presentation but cannot reorder logical events or change their outcomes.

Fixtures are non-authoritative sample data. They contain synthetic credentials and accounts only. Their IDs and digest appear in export and evidence. If a user must choose among success/failure variants, that control is labeled as simulation tooling and excluded from the authored product control inventory. It does not replace reachable product transitions.

## 5. Route and history semantics

The canonical route address is `#wf/<encoded-namespace>/<encoded-page-id>` plus `?variant=<encoded-variant>` when selecting a review projection. UTF-8 percent-encoding is applied to segments, never to the separators. Runtime route selection uses identity, not document index, title, slug, label or canvas location. An absent fragment selects the explicit entry. A malformed or unresolved fragment renders an accessible error view that displays the address and an actual link to entry; it does not silently open the first page.

Internal anchors carry their real canonical href. Plain primary clicks update the route/history; modifier clicks, middle clicks, copy-link and open-in-new-tab retain browser behavior. In file profiles no server path fallback is used. External URLs use native navigation and opener isolation. Forbidden schemes, credential-bearing URLs, control characters and ambiguous internal/external declarations are compilation errors. A bare source navigate string is a screen identifier; URL-shaped bare strings are rejected with an explicit-target diagnostic.

Pushing the already-current route is idempotent. Replace changes the current entry without adding one. Browser back/forward restores the addressed screen and session state of the existing running app; it does not replay submit or external effects. On initial load or reload, the addressed screen uses fresh initial state/fixtures; its entry preconditions must be represented by that profile's fixture, or the authored guard routes to a permitted alternative. History stores only route identity and app history sequence, never secret state. Core's history actions do not move outside the app's known history range; the browser's own history controls remain under browser ownership. When a same-app popstate has already changed the URL and exit rejects it, the runtime retains the committed UI/state, performs the inverse traversal using recorded app history sequence, and consumes the compensating event without replaying exit. Interaction remains suspended until the committed address is restored. For an unrecorded same-document address, rejection restores the committed URL with replaceState and starts a new known app-history range at that entry; the browser retains ownership of its other entries. A failed transition may not leave rendered route and browser address disagreeing.

Review `variants` project a screen under named states without changing its identity. `when` removes content from excluded board projections; runtime guards change the current logical screen's visible/enabled state. A scenario's state transitions must use executable state declarations and operations. They are not proved by switching a review-board selector.

## 6. Native controls, keyboard and focus

Text input, textarea, select, checkbox, radio, switch and slider emit native controls with associated labels. Each label's for/id pair is scoped to the rendered instance. Control values are bound once. Checkbox/switch bind booleans; text/select/radio bind declared scalar types; number/slider reject non-finite conversion. Empty numeric input is an invalid pending edit, not numeric zero. Forms own unique submission names. Buttons default to type=button; submit/reset are explicit and name an owning form. Enter submission uses the same handler as activating submit.

Links remain anchors, actions remain buttons. An icon-only action requires an accessible name and visible focus cue. Disabled/hidden/readonly are different states; readonly does not remove focus, disabled blocks activation, hidden removes focus and accessibility exposure. Loading uses aria-busy and the declared concurrency policy. Mutation that hides the focused element moves focus to its nearest visible owning region, then the screen heading if needed.

Modal uses native dialog semantics (or an equivalent implementation with the same tested behavior): focus enters the declared initialFocus, otherwise the first focusable child, otherwise the dialog container. Background content becomes inert. Tab stays within the top modal. Escape closes the top closable overlay and returns focus to the opener if still visible/enabled, otherwise to the active screen heading. A nested modal preserves the prior overlay's focus context. Non-modal drawer/popover does not trap focus. Accordion uses details/summary behavior. Tooltip opens on focus and hover, closes on Escape and does not contain interactive content.

Tabs have tablist/tab/tabpanel relationships, one selected tab and roving tabindex. Left/Right (Up/Down in vertical mode), Home/End move focus; Enter/Space activates. Disabled tabs are skipped. Dropdown uses a button trigger, menu/menuitem semantics, arrow/Home/End navigation and Escape return. A route navigation is never inferred from tab selection. Status messages use an appropriate live region without stealing focus. Critical errors remain until explicitly resolved; toast dismissal is an explicit user or fixture action.

These mappings use [HTML hyperlinks](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-a-element), [forms](https://html.spec.whatwg.org/multipage/forms.html#the-form-element) and [dialog behavior](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element) as the platform contract. ARIA decoration alone does not implement those behaviors.

## 7. Fixed boards and accessible execution

Each profile fixes width and height before layout. Page device, viewport and width/height declarations must resolve to the same dimensions when combined; otherwise WW_VIEWPORT. A page with no dimension declaration uses its explicit profile. Shared shell/page pairs must use the same fixed profile. Desktop/mobile are distinct profiles; breakpoint attributes are selected against that profile once. Resizing the host never changes the authored board. Host scale/scroll/clipping can change its presentation without changing its internal layout.

Canvas places explicit coordinates exactly. Unplaced boards flow horizontally from x=0/y=0 in input order, advancing beyond already placed bounding boxes with a 64px gap. Auto-placement never overlaps an explicit board; explicit overlaps remain authored and are reported as such. Bounds include negative positions. Canvas pan/zoom, editor titles, minimap, selection handles and review next/previous buttons are host-owned chrome and absent from app HTML.

The app supplies a discoverable accessible execution view from the same model, with the same route, controls, state store and operations. It reflows ordinary forms, explanations and requirement panels at 320 CSS px and preserves content/function at 200% text enlargement. Only regions requiring two-dimensional layout use the corresponding reflow exception. Fixed visual boards are not a blanket exception. Switching representation keeps logical focus, input values and pending operations; it does not execute hidden duplicate controls. There is one active interactive representation, and the inactive view is inert.

Acceptance applies [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/), including text enlargement, reflow, text spacing, keyboard, names/roles/values, focus visibility, contrast, errors and target size. A screen-reader-only text dump does not establish equivalent execution. Alternate-view discovery, complete processes and every authored operation are tested. SVG and static tiles are not presented as substitutes for accessible execution.

## 8. Neutral rendering and isolation

The neutral profile defines surfaces white/#f4f4f5, text #18181b, muted text #52525b, borders #71717a and focus #18181b with a 2px outline plus 2px offset. State uses text, line style and icons as well as tonal differences. There is no color-only status. Radius is 4px when rounded; pill uses half-height; outline is 1px; elevation tokens use neutral 1/2/4/8px shadows for sm/md/lg/xl. Font is the profile-pinned self-hosted font asset, with a documented system fallback; rendering evidence records which font loaded. Core CSS values do not define the target product's brand system.

Every style selector is scoped to the wireweave root. DOM IDs are `wf-` plus lowercase SHA-256 of UTF-8 JCS `{identity:LinkedIdentity,projectionId}`; projectionId is the explicit board/profile projection key. Repeated/canvas instances share a logical source identity only when their declaration and full instance path agree. A digest collision or duplicate identity is an error, never a suffix chosen from DOM order. Component, overlay, form, label and requirement ID references use the same scope function. No duplicate DOM ID is permitted. Fragment CSS is returned separately and inserted once by the host; app CSS and official runtime are embedded once. Runtime code cannot be authored inside a DSL field.

App assets are supplied bytes verified by digest/byteLength/mediaType. PNG/JPEG/WebP and sanitized SVG are accepted; SVG scripts, foreignObject, event handlers and external references are rejected. Fonts are verified WOFF2 bytes. Unknown/missing assets error in app compilation; designated placeholders are authored explicitly. Default app rendering does no fetch, remote font lookup, tracking, WebSocket, worker or storage access. Explicit external link navigation remains user-controlled and is not an asset fetch permission.

Requirement HTML panels and a `<script type="application/json">` data block derive from the same fixed registry. Data-block JSON escapes `<` as `\u003c` and rejects invalid Unicode, preventing `</script>` termination. Attribute/text escaping and URL validation are context-specific. Rendered markup never includes secrets, raw provider tool output or developer-local absolute paths. [HTML data blocks](https://html.spec.whatwg.org/multipage/scripting.html#the-script-element) are non-executing; their contents still require safe HTML serialization.

Studio iframe previews use sandbox isolation with only the official runtime capability and no host credentials, navigation grants or unrestricted message handlers. Messages carry instance ID, protocol version and revision; hosts validate origin/source and payload. Output grants are explicit and reflected in the artifact manifest. App compilation emits attribute-derived styles into scoped classes in its fixed stylesheet, and runtime changes classes rather than creating style attributes. CSP includes only hashes of the fixed inline runtime/style and approved data resources; it denies connect, object and unapproved frame sources. Browser tests observe network requests, console errors, policy violations and host-boundary escape attempts.

## 9. Numeric resource profile

`standard-1` limits are mandatory upper bounds, not implementation targets. Hosts can reject smaller limits at admission with a named profile; they cannot raise these silently or truncate data. Parsing and expansion check budgets before allocating or recursing.

| Resource                                               |               Bound |
| ------------------------------------------------------ | ------------------: |
| UTF-8 bytes per source module / bundle                 |      8 MiB / 64 MiB |
| Modules / import depth                                 |            256 / 64 |
| Parsed nodes / expanded nodes                          | 250,000 / 1,000,000 |
| Structural or expression depth                         |                 128 |
| Screens / variants per screen                          |         2,000 / 128 |
| Repeat count / parameters or slots per component       |         1,000 / 128 |
| State declarations per scope / handlers per node       |          4,096 / 32 |
| Operations per handler / microsteps per semantic event |           128 / 256 |
| Queued semantic events / concurrent fixture requests   |         4,096 / 128 |
| Fixture definitions / steps per fixture                |      10,000 / 1,000 |
| List records / fields per record                       |      10,000 / 1,000 |
| Fixture delay or timeout                               |          600,000 ms |
| Asset bytes each / all embedded assets                 |     16 MiB / 32 MiB |
| Registry entries / requirement references per node     |     100,000 / 1,024 |
| Serialized HTML bytes / total diagnostics              |      64 MiB / 1,000 |

Crossing a runtime bound aborts the current transaction, retains the prior committed state, cancels its pending effects and records a typed limit error. The UI exposes recovery/reset; it does not freeze in a spinner or continue an unbounded immediate-transition loop. Time measurement used for local UI performance is separate from logical fixture time.

## 10. Trace and acceptance

A runtime trace record contains schemaVersion, app/model/profile digest, sequence, resetGeneration, virtualTime, route, logical source and rendered instance, handler/operation ID, executionClass, normalized event, state-delta digest, result and diagnostic references. Sensitive state values are redacted before storage; their raw hash is not exposed as a guessing oracle. Results distinguish succeeded, failed, skipped-dependency, guard-false, busy, history-boundary, specified-unexecuted, stale-response and cancelled. Trace sequence is append-only within a generation; reset is an explicit record.

Conformance compares identical input models, profile/fixture bytes and event sequences for identical semantic traces and compiled HTML bytes. Browser rendering comparisons also pin browser/font/OS and viewport. DOM visibility, accessible state, route/history, focus, pending/error/retry, duplicate submit and network effects are observed in the actual exported file. Unit snapshots and host screen paging cannot establish that acceptance. The producer and verifier are distinct roles; a generated success message is input to verification, not evidence of success.

`RuntimeInput` is the conformance driver's closed input union: event, advanceClock, reset and address. An event source is the full LinkedIdentity copied from sourceMap, including its screen/shell root and typed use/repeat path; an empty path addresses a non-repeated root control. Paths are copied from source maps, not guessed from DOM order. value/checked/key are accepted only for the matching native event contract. address uses the same browser-fragment parser as a real location change. Drivers cannot inject enter/exit, fixture responses or operation success directly.

Each `RuntimeCase` references a valid corpus example and executes its ordered steps from a fresh reset. The driver pauses automatic time. Each `RuntimeExpectation` compares the named state subset by structural equality, route identity, pending-request count and reserved-state count after draining that input's synchronous microsteps. Missing expected fields mean no assertion, not zero. A runtime case passes only from actual reducer/browser evidence; schema validation of the case is its input-shape proof. The corpus covers failed-fixture retry, cancelled requests writing surviving app state, exit state updates before unmount, and caller-owned controls in component slot fills.
