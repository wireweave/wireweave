# Wireweave public tools and integrations

Contract: `core/tooling`. Language `4.0.0`; protocol schema `1.0.0`.

## 1. Shared tool contract

The npm library, SDK local dispatch, CLI, MCP server, markdown integration and editor use one versioned Core grammar/catalog and result model. Deterministic parse/validate/render/analyze/diff/export/grammar calls execute locally and require no account or API key. Selecting a remote service is an explicit capability choice under `contract:studio/collaboration`; a failed local call cannot fall back to a remote call or transmit its input.

`@wireweave/core` publishes ESM and CJS with declarations. Public subpaths are `.`, `/parser`, `/renderer`, `/spec`, `/app`, `/interaction`. `/spec` exports the language/schema/catalog fingerprints and a URI-to-bytes resolver containing the exact immutable transitive schema closure, including the product Registry schema and its digest. Public npm consumers validate offline using those bundled resources; they need no private workspace, product service, account or network schema resolver. Every export in the release manifest must exist in the packed artifact, have substantive contents and resolve all imports. Importing any entry is side-effect-free: no process globals, prototype mutation, filesystem/network I/O, timers or account initialization. Core does not depend on host, SDK, provider or Wireweave binding packages.

The release pins Node engine, Core/language/schema versions, icon and Unicode datasets, renderer/runtime digest and supported browser profiles. Tool discovery reports these values. A client cannot claim support from a package name or semver range alone. The installed release is selected at installation/admission; a plugin does not download npm latest during every invocation.

## 2. Pure library API

Types named below refer to the corresponding definitions in [schema.json](schema.json). `ParsedDocument` includes normalized modules and app options; `AppBundle` fixes a complete input set. `LinkedApp` is immutable, opaque and version-tagged: only a successful linker/semantic validator constructs it. Callers cannot turn arbitrary JSON into LinkedApp with a type cast.

`Result<T>` is `{ok:true,value:T,diagnostics:Diagnostic[]}` with no error-severity diagnostic, or `{ok:false,value:null,diagnostics:Diagnostic[]}` with at least one error. A recovered syntax tree is in a separate `partial` field and is always invalid. A count/limit truncation retains the failure flag. Diagnostics use [LANGUAGE §10](LANGUAGE.md#validation-and-conformance). Programmer misuse throws TypeError; authored input errors use Result except for the explicit throwing parse facade.

| API                                               | Input → output and guarantees                                                                                                                                               |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| parse(source, options?)                           | UTF-8-decoded string + `{sourceId,languageVersion}` → ParsedDocument; throws ParseError with structured diagnostics on authored errors                                      |
| tryParse(source, options?)                        | Same input → `Result<ParsedDocument>`, optional invalid partial syntax tree; empty input is a valid empty fragment document                                                 |
| isValid / getErrors                               | Parse and semantic-fragment validation as boolean / diagnostics; do not suppress missing required imports                                                                   |
| printWireframe(document)                          | ParsedDocument → canonical source; errors on invalid/unbound construct shapes; does not inline external product facts twice                                                 |
| formatWireframeCode(source, options?)             | parse+print with the same normalization and error model                                                                                                                     |
| parseToCanvas(source, options?)                   | ParsedDocument plus canonical board projections/positions; not an executable app                                                                                            |
| createAppBundle(documents, options)               | Complete parsed documents + explicit app ID/entry/profile/registry/fixtures → `Result<AppBundle>`; verifies content/source digests                                          |
| linkApp(bundle)                                   | AppBundle → `Result<LinkedApp>`; performs all import, template, state, route, registry and resource checks, not symbol lookup alone                                         |
| compileApp(linkedApp)                             | LinkedApp → `Result<AppArtifact>`; no output when compilation fails                                                                                                         |
| linkAndCompileApp(bundle)                         | Exactly linkApp then compileApp with the same diagnostics and output; does not bypass semantic validation                                                                   |
| renderSite(bundle)                                | Convenience alias for linkAndCompileApp; returns AppArtifact, not an unqualified partial HTML string                                                                        |
| render / renderPage                               | ParsedDocument / page + fixed fragment profile → `Result<FragmentArtifact>`; render uses canvas composition for multiple review boards                                      |
| renderToHtml                                      | Fragment result → standalone static-document wrapper; manifest identifies static fragment scope; executable app export uses compileApp                                      |
| renderCanvas / layoutCanvas                       | Validated board projections + placement options → CanvasArtifact / PlacedPage[] with deterministic bounds; no host pan/zoom                                                 |
| renderToSvg                                       | Validated board projections + SVG profile → `Result<{svg,width,height,manifest,diagnostics}>`; static semantics and asset limits remain explicit                            |
| validate / isValidAst / getValidationErrors       | ParsedDocument or AppBundle + mode fragment/app → structured diagnostics / boolean / diagnostics; app mode runs complete linker semantics                                   |
| extractTransitions                                | LinkedApp → node/edge graph with source/operation IDs, guards, executionClass and obligation refs; same targets as runtime                                                  |
| createRuntime / reduceEvent                       | LinkedApp + profile fixture input / RuntimeInput → runtime snapshot / pure next snapshot and effects/trace; deterministic conformance seam                                  |
| advanceClock / resetRuntime                       | Runtime snapshot + integer duration / reset request → next snapshot and ordered due events; no wall-clock dependency                                                        |
| analyze                                           | ParsedDocument or LinkedApp + selected axes → component/data/accessibility/complexity/layout statistics with denominator and unavailable flags; no proof of UX completeness |
| diff / areIdentical / getChangeSummary            | Two same-version canonical documents → added/removed/changed/moved IDs and field paths / semantic equality / summary; labels are not matching keys                          |
| exportToJson / importFromJson                     | Canonical schema values → JSON bytes / `Result<ParsedDocument or AppBundle>`; no type information or requirements lost                                                      |
| exportToFigma                                     | Linked semantic nodes + explicit target mapping profile → mapping document and loss report; no server write or undocumented import compatibility claim                      |
| walkDocument / walk / find / findAll / findByType | Deterministic depth-first traversal, preserving source child order; runtime instances and reusable definitions are selectable distinct domains                              |
| getValidAttributes / attributeFor / catalogs      | Language revision + element kind → contextual domains/descriptions; icon names are a pinned dataset, not global language keywords                                           |
| resolveViewport / DEVICE_PRESETS                  | Explicit profile inputs → fixed dimensions and typed error; unknown presets never fall back silently                                                                        |
| calculateViewportScale / wrapInPreviewContainer   | Fixed dimensions and caller container → scale/wrapper; presentation-only, never page reflow or route selection                                                              |

AST type exports include ParsedDocument, AppBundle, Module, Node, Definition, State, Guard, Expression, Handler, Operation, Effect, Fixture, Profile, Diagnostic, logical ID and rendered instance ID types. Existing family names such as WireframeDocument/Page/Component refer to their schema-backed types in this language release. Kind guards narrow those types without accepting arbitrary objects. An export marked internal is not consumed through private source paths.

AppArtifact contains `{html,mediaType:'text/html',byteLength,digest,modelDigest,profileDigest,runtimeDigest,registryDigest,entry,screenIndex,operationIndex,sourceMap,diagnostics}`. FragmentArtifact contains `{html,css,profileDigest,sourceMap,requirementRefs,diagnostics}`. CanvasArtifact adds boards and bounds. A source index references original bytes and spans; it does not silently include confidential full sources. Diagnostic and artifact metadata are serialized separately from HTML except for the explicitly embedded machine index.

## 3. SDK dispatch and I/O admission

`dispatch({schemaVersion,requestId,tool,input,execution,output})` has `execution=local|remote`. The default is local. Local dispatch calls the functions above in-process and cannot read credentials. Remote dispatch requires an explicit endpoint/account capability and source transmission grant. Generation calls use `contract:harness/protocol`, not an alternative parser or opaque hosted generation path.

A source input is either `{source,sourceId,languageVersion}` or `{bundle}`; parse accepts source only, compile accepts bundle only, and adapters reject conflicting forms. File inputs are expanded by the caller into bytes and a source manifest before Core execution. The resolver contract is `resolve({moduleId,expectedDigest}) → {sourceId,bytes,digest,byteLength}` under caller-owned allowed roots, total bytes and symlink checks. A dependency is never fetched because a document contains a URL. Remote selection cannot change the language semantics or exception model.

Output mode is inline or file. File mode requires an allowed output root and filename; the host writes a temporary sibling, verifies bytes/digest, then atomically replaces the target subject to expected existing digest. Path traversal, symlink escape and unintended overwrite are errors. A storage receipt includes the committed path, digest and byte length. The parser/compiler never returns a file-written success merely because it produced a string. Stdout is not an output directory.

Transport request IDs identify delivery; idempotency keys identify repeatable effects. Retrying a deterministic parse may recompute; retrying an output write with the same key/body returns the stored receipt and a different body conflicts. Tool errors preserve code/phase/source span across every adapter. Human summaries are derived views and never replace machine diagnostics.

## 4. CLI

The binary is `wireweave`. Node >=22.13.0 and the exact package version in the installed ToolchainProfile are required. `--version` prints tool, Core, language, schema and runtime versions; `--help` prints the catalog for those versions. Installation can use `npm install --global @wireweave/cli@<pinned-version>` or an installed package manager lockfile. Angle-bracket values denote user-supplied versions, not literal shell arguments.

All local commands accept `--language-version 4.0.0`, `--format json|summary`, `--diagnostics <path>` and a byte-limit profile. Diagnostic output goes to stderr unless a file is selected; successful primary output goes to stdout or `--output`. Multiple input globs expand before Core execution, are sorted by normalized relative path and are recorded in the input manifest.

| Command                 | Required input                    | Output/options                                                                                                        |
| ----------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| parse                   | source file or `-` for stdin      | canonical parsed JSON; `--include-locations` adds a sidecar map                                                       |
| format                  | source file                       | canonical DSL; `--check` compares bytes without writing; `--write` uses guarded atomic output                         |
| validate                | source file or app bundle         | `--mode fragment\|app`; unknown attributes are errors; `--strict` explicitly selects the same strict behavior         |
| render                  | source file                       | `--output`, `--profile neutral-fragment`, `--full-document`; static scope is recorded                                 |
| compile                 | app bundle file                   | `--output app.html`; strict app artifact with inline content/resources                                                |
| list-components         | none                              | complete element-aware catalog; `--category`, `--format`                                                              |
| grammar                 | none                              | `--format json\|text`; grammar/schema/runtime fingerprints and supported attributes                                   |
| validate-ux             | source/bundle                     | independent UX-rules package; categories, min-severity, disabled-rule IDs, max-issues; excluded rules remain reported |
| analyze                 | source/bundle                     | selected statistics axes, `--no-accessibility`, `--no-complexity`; unavailable is not zero                            |
| diff                    | two source/bundle files           | `--ignore-attributes`, `--ignore-order` only affect the explicitly labeled comparison; not canonical equality         |
| export-json             | source/bundle                     | `--include-locations`, `--no-pretty-print`, `--output`                                                                |
| export-svg              | source/bundle                     | fixed board/viewport selection and manifest; no interactive claim                                                     |
| export-figma            | source/bundle plus target mapping | mapping JSON and loss report; no external Figma mutation                                                              |
| login / whoami / logout | selected service profile          | auth state only; credentials stay in host secret storage; whoami masks them                                           |

`--theme light|dark` on static/documentation output selects neutral surfaces (light: white surface/#18181b text; dark: #18181b surface/#fafafa text/#a1a1aa muted and border); it cannot inject brand tokens or change behavior. Strict app output uses its profile, and conflicting theme flags error. Exit codes are 0 success, 1 environment/I/O/internal failure, 2 language/schema/semantic rejection, 3 independent UX gate failure, 4 unsupported capability/version, 130 cancelled. Errors never emit an apparently complete app to stdout.

Core/CLI local commands do not consult WIREWEAVE_API_KEY. For explicit remote calls, service profile selection order is flag, environment, saved profile; an API key is obtained by interactive stdin, host secret reference or environment injection, never URL/query parameter or persisted document. Secret storage and browser OAuth callback validation belong to the host service contract. Authentication, rate-limit headers, subscription tiers and prices are owned by `contract:product/policy` and `contract:studio/collaboration`, not repeated in this tool catalog.

## 5. MCP and agent plugins

The MCP server exposes the same tool schemas and local defaults. Stdio is the baseline transport: stdout is exclusively MCP frames; diagnostics go to stderr. Tool discovery includes exact schema versions, language/runtime capability and a catalog digest. Required capabilities are checked before accepting a call. Cancellation stops pending work/output admission; a completed deterministic artifact is distinguishable from a stored artifact receipt.

| MCP tool                                                              | Shared operation                                   |
| --------------------------------------------------------------------- | -------------------------------------------------- |
| wireweave_parse                                                       | parse                                              |
| wireweave_validate                                                    | validate                                           |
| wireweave_render_html / wireweave_render_html_code                    | render with identical input/output semantics       |
| wireweave_render_html_file                                            | render plus host-controlled atomic file output     |
| wireweave_compile_app                                                 | strict app bundle compilation                      |
| wireweave_grammar                                                     | versioned grammar/schema/catalog                   |
| wireweave_list_components                                             | element-aware component catalog                    |
| wireweave_analyze / wireweave_diff                                    | analysis / canonical structural comparison         |
| wireweave_validate_ux                                                 | independent UX rules with exclusions reported      |
| wireweave_export_json / wireweave_export_svg / wireweave_export_figma | explicit format conversion with loss/manifest data |

A client registration specifies the pinned executable and args, e.g. command `wireweave-mcp`, args `[]`, environment `{}` for local tools. Client-specific config location and envelope are provided by the installed ClientProfile for Claude Desktop, Cursor or VS Code; they are not inferred from a client brand or outdated filesystem convention. Setup verifies executable discovery, transport handshake, catalog/version digest and a local parse+render with network blocked. Restart/reconnect after changing registration. Failure diagnostics identify executable/PATH, malformed config, missing capability or version mismatch separately from service authentication.

A Claude Code plugin's `/wireweave <command>` delegates the same structured arguments to the installed CLI. It does not concatenate untrusted source into a shell command, hold its own authentication state, recreate a grammar guide or fetch latest during execution. Shell metacharacters in source, paths and labels remain data. Generation/refinement commands dispatch the authorized Wireweave binding with fixed source revisions; deterministic tools do not implicitly select a provider.

HTTP mode is selected with `--http` or `WIREWEAVE_TRANSPORT=http`. It implements [MCP Streamable HTTP 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). `/mcp` accepts initialization POST, subsequent POST/GET with the negotiated protocol/session headers, and DELETE for termination. Unknown/expired sessions return 404 and are never silently reinitialized. Unsupported negotiated protocol returns 400. Network disconnection alone is not cancellation.

`WIREWEAVE_MCP_HOST` defaults to 127.0.0.1; `WIREWEAVE_MCP_PORT` defaults to 3305 (integer 1–65535); `WIREWEAVE_MCP_MAX_SESSIONS` defaults to 10 (integer 1–1024). Invalid configuration fails startup. Initialization reserves a session slot atomically, including in-flight handshakes; exhaustion returns 503 with Retry-After=1. Idle sessions expire after 30 minutes; termination releases the slot and cancels their uncommitted tool work. GET `/health` exposes only status, transport, activeSessions and tool count, with no source, credentials or session IDs. Other paths return 404.

HTTP transport authentication is independent of an account API key: every `/mcp` request requires a host-supplied `WIREWEAVE_MCP_TOKEN` bearer credential. Absence fails HTTP startup; the token is never logged. Host validates the Host header and an exact Origin allowlist (`WIREWEAVE_MCP_ALLOWED_ORIGINS`, comma-separated origins; empty rejects every request containing Origin). Missing Origin from a native client is allowed only after bearer verification. Invalid Origin returns 403; wildcard CORS is prohibited. A non-loopback binding additionally requires an explicit deployment profile with TLS termination, trusted-proxy addresses and per-principal capability/allowed-root policy; without it startup fails. Sessions bind to the authenticated principal and cannot enlarge its filesystem or remote-service grants. Stdio uses the launching process's granted capability and needs no HTTP token.

`@wireweave/agent-prompts` exports `buildGrammarPrompt(options)` and `buildCompactGrammarPrompt(options)`. They return text derived from the pinned language catalog, with version/digest metadata available beside the text. The compact variant reduces explanatory prose, never removes required syntax constraints or substitutes another grammar. These functions perform no LLM, filesystem or network calls and contain no private orchestration policy.

## 6. Editor, catalogs, UX and markdown integrations

VS Code/Cursor associate `.wf` and `.wireframe` with the same language. Syntax coloring, completion, hover, diagnostics and format use the installed language catalog. Context-sensitive item types and icon datasets are resolved at the element position. A change increments the source revision; preview and diagnostics for an older revision are dropped, not painted onto the new document. sourceMap spans use UTF-16 offsets, matching editor coordinates.

Editor commands are Open Preview, Open Preview to Side, Export as HTML, Generate, Improve, Login and Show Usage. Preview supports fixed board overview and a separate app execution view. Generate/Improve produce a candidate in a new document/diff; they never overwrite current edits or silently auto-accept streaming text. Selection edits carry exact range/base digest. SecretStorage or equivalent host credential storage holds service credentials, never settings.json or DSL. Remote capabilities follow explicit authorization; local preview/format do not require login.

Editor settings are `wireframe.theme=auto|light|dark` (default auto, resolves the host theme into a neutral preview palette), `wireframe.autoPreview:boolean` (default false), and `wireframe.previewWidth` (default 1200, positive CSS pixels). Preview width controls only host presentation scale; it cannot change a page's authored viewport or choose a different route. Settings and preview state do not contain source credentials.

`@wireweave/language-data` root exports component/attribute maps, valid names, category/value/spacing catalogs and the lookup/validation helpers `getComponent`, `getComponentByNodeType`, `getAttribute`, `getValidChildren`, `isValidChild`, `getComponentAttributes`, `getComponentsByCategory`, `getAttributeTypeLabel`, `formatAttributeValues`, `isComponent`, `isAttribute`, `getComponentNames`, `getAttributeNames`, `getCategories`. Every result is version-tagged and derived from Core; source categories and semantic checks have one owner. Invalid context returns a diagnostic, not a broader global attribute list.

The `/monaco` subpath supplies `registerWireframeLanguage`, Monarch tokens/configuration, completion/hover providers, `validateCode` and diagnostics setup/disposal. `/codemirror` supplies `createTokenizer`, `getLanguageConfig`, `createCompletionSource`, `createHoverTooltipSource`, `validateCode` and `createLinter`. Monaco and CodeMirror peers are optional for root-only consumers; importing one adapter cannot load the other editor. Registration is scoped to the host editor instance, is idempotent for the same catalog version, and returns disposables for installed services. Diagnostics include exact source revision and are removed when a document/editor closes.

`@wireweave/ux-rules` exports `validateUX`, `isUXValid`, `getUXScore`, `getUXIssues`, `formatUXResult`, `allRules`, `rulesByCategory` and `getRulesForCategories`. Its versioned rule catalog owns stable rule IDs, definitions, applicable node kinds and severity; rule count is not a separate hardcoded contract. Categories are accessibility, usability, consistency, touch-target, navigation, form, feedback, content, data-display and interaction. Options are categories (empty=all), minSeverity (default info), maxIssues (default 100, positive integer), customRules and disabledRules. Duplicate/unknown rule IDs and thrown rule checks are explicit errors; no skipped check becomes passed. Custom executable rules are installed by trusted host code, never serialized DSL.

A UX issue has ruleId, category, severity=error|warning|info, message, description, suggestion, logical path/nodeType and source location. Results include catalogDigest, valid, score, rawScore, complexity, issues, category passed/failed/warnings, severityCounts, excludedRules, evaluatedCount and truncated. All applicable checks run before the displayed issue limit; an incomplete run cannot claim valid. `valid` means zero errors in the evaluated scope, not whole-product or WCAG conformance. With counts E/W/I, rawScore=clamp(100−10E−3W−I,0,100), score=clamp(round(100−10E−(3W+I)×3/max(3,C)),0,100), where C is Core's fixed-version complexity score. Missing complexity makes the adjusted score unavailable rather than invented. Neither score substitutes for scenario acceptance; exclusions and denominator are always visible.

`@wireweave/markdown-plugin` exports `renderWireframe(code,options)`, `markdownItWireframe`, `markedWireframe` and `remarkableWireframe`; every adapter uses the same parser/output contract. VitePress uses the markdown-it adapter. Framework adapters for remark/MDX and Docusaurus use the same closed render contract and isolated app admission. Fences `wireframe`, `wire` and `wf` share the grammar. Options are:

| Option                             | Domain, default and meaning                                                                                                                                  |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| format                             | html, html-preview, svg, svg-img, app; default svg-img. svg-img embeds the same static SVG bytes in an image; html-preview wraps a fragment with host scale. |
| theme                              | light or dark; default light; neutral palette only                                                                                                           |
| containerClass                     | Space-separated CSS class tokens; default wireframe-container; escaping is mandatory and arbitrary markup is rejected                                        |
| errorHandling                      | code, error, both; default both; safely escaped source, diagnostic, or both                                                                                  |
| containerWidth                     | Nonnegative CSS pixels; default 0 means no scaling                                                                                                           |
| maxScale                           | Positive finite scale; default 1; bounds presentation scale, never model dimensions                                                                          |
| profile / width / height / padding | Fixed Core output profile and nonnegative outer padding; explicit dimensions must agree with the authored viewport                                           |

Global defaults are overridden by block options; inconsistent dimensions error. All boards retain their own viewport; html-preview measures the complete board bounds, never only the first page. HTML fragment is static/semantic embedding. App mode requires a closed bundle and isolated iframe, not an inline page script. All adapters expose machine diagnostics through a callback/sidecar even when errorHandling displays only source code; rendering an error block is not build success.

A fence's source bytes, options and language digest key the cache. Invalid input produces a diagnostic block with safe source excerpt and no executable markup. CSP/style isolation is part of the host contract; resetting all CSS cannot erase accessible focus and semantics. Static export records unsupported SVG/foreignObject features. Documentation builds never call an LLM, remote grammar endpoint or service to render a fence.

## 7. Build, compatibility and evidence

Grammar/AST/schema changes require one coherent release: grammar → parser generator → schema/type metadata → element/attribute catalogs → printer/renderer/runtime → SDK/CLI/MCP descriptions → editor/markdown integrations. Generated files are produced by their generators and not manually edited. The EBNF and JSON Schema are release inputs; executable Peggy grammar is an implementation that must pass those contracts. Keyword removal, meaning changes, narrowed domains or newly required canonical fields require a major language version and explicit import migration.

Migration is an explicit command returning source/AST diff, identity preservation and diagnostic report. Unsupported old syntax is not interpreted using guesses. Display vocabulary aliases in prose are not silently accepted as language tokens. A migration consumes an explicit source language profile and produces this canonical language; failed migration retains source bytes. No document includes both competing normative snapshots.

Release checks cover source/dist freshness, all exports/subpaths in the packed archive, no import side effects, parser/printer and catalog closure, positive/negative schema fixtures, semantic fixtures, browser app conformance and actual consuming adapters. Workspace source and published dist are tested separately. A schema example pass proves its declared JSON shape only; parser support and runtime behavior require their own traces.

For library code, run project typecheck, lint, unit tests and affected packaging gates. For contract changes, validate the JSON Schema with a Draft 2020-12 validator, load referenced product schemas locally from the design-release registry, validate all corpus entries and compare EBNF terminals/catalog coverage. The packed `/spec` resolver is tested with network and private-repository access denied; every transitive referenced schema must be present and digest-verified. Unknown external schema references fail closed; validation does not download a moving schema from the network. Evidence includes exact file digests, command, tool version, result and scope.
